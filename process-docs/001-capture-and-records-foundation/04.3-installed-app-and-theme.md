# Implementation Sub-Plan 3 — Installed App and Theme

> **Approved** by @user on 2026-09-13. Locked — changes require a change record (§7 of the rules).

Parent: [Implementation plan index](./04-implementation-plan.md)
Context: [PRD](./01-prd.md) · [Design](./02-design.md) · [Build plan](./03-build-plan.md)

This slice must be buildable from this document plus the index, with nothing
else open. It restates nothing that lives in the index.

Frontend only, no backend change. Shorter than the other two slices because
there is less here: three static surfaces, a manifest, and a CSS rule that
already does most of the work on its own.

## 1. What works when this lands

Slashit can be added to a home screen and opened without browser chrome, reads
every cached record with no connection and refuses a capture honestly instead
of queuing it, and tells the user when a new version is ready without forcing
a reload. Every screen from slices 1 and 2 renders correctly in dark mode
when the device is set to it.

## 2. Requirements covered

| FR / NFR | How this slice satisfies it |
|---|---|
| FR-39 | `vite-plugin-pwa` generates the manifest and registers the service worker. `InstallPrompt` shows once per browser session (`sessionStorage` flag), dismissible, and never re-shown after a dismiss or an install |
| FR-40 | The service worker precaches the app shell and runtime-caches every `records`/`record` query response, cache-first. `useOnlineStatus` refuses capture in the input itself, before submit, when `navigator.onLine` is false |
| FR-41 | `useUpdateAvailable` listens for the worker's `waiting` state and shows `UpdateBanner`. Reloading only happens on the user's click; nothing in the capture input is cleared by that reload, since MobX state does not survive a full reload today regardless — see the gap noted in §6 |
| product.md §10, Theme | `design-system/tokens.css` (populated with both light and dark values in slice 1) is read live through `@media (prefers-color-scheme: dark)`. No override exists, per Q13 of the design; there is nothing here to build for one |

## 6. Error handling

| Failure | Detected by | User sees | System does |
|---|---|---|---|
| Browser does not support `beforeinstallprompt` (e.g. iOS Safari) | The event never fires | Nothing. No install banner, no error | `InstallPrompt` renders nothing; no fallback UI in V1 |
| Capture attempted while offline | `useOnlineStatus()` false at keystroke time | The input shows the offline refusal inline, submit disabled | No mutation fires. FR-40's "nothing is queued" holds because nothing is ever sent |
| Service worker registration fails (e.g. private browsing) | `vite-plugin-pwa`'s registration promise rejects | Nothing surfaced to the user | App runs uncached, online-only. Logged to the console in dev, not reported anywhere in V1 |
| A reload from `UpdateBanner` happens mid-capture | Not detected | In-progress input is lost | **Known gap, not fixed here**: FR-41 says "anything typed survives," but capture input lives in React/MobX state, which a hard reload always discards, independent of this slice. Persisting a draft across a reload is a Capture-domain concern (04.1), out of this slice's scope. Named here so it is not silently assumed done |
