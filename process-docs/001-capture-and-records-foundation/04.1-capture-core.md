## 1. What works when this lands

Type a command in the Command Center and get a task, a question, or an honest
refusal. Every outcome in the design's four Command Center flows (§3: clean
capture, capture with a gap, input without a command, refusal) works against
the real gateway and a real database, not the canvas prototype's mocked date
heuristic.

## 5. Internal contracts

### Where `Task` lives, and why

```python
# app/domains/records/interfaces/dtos.py
from dataclasses import dataclass
from datetime import datetime
from typing import Literal
from uuid import UUID

import strawberry


@dataclass(frozen=True)
class TaskDTO:
    id: UUID
    user_id: UUID
    title: str
    due_at: datetime | None
    status: Literal["pending", "done"]
    is_overdue: bool
    origin: Literal["command", "edit"]
    original_input: str | None
    created_at: datetime
    updated_at: datetime


@strawberry.type
class Task:
    """The crossable GraphQL shape. Lives here, not under graphql/, so it may
    cross per repo-rules.md §6.2 — the same placement gateway used for
    Extraction in errors.py."""

    id: strawberry.ID
    title: str
    due_at: datetime | None
    status: str
    is_overdue: bool
    origin: str
    original_input: str | None
    created_at: datetime
    updated_at: datetime


def task_dto_to_type(dto: TaskDTO) -> Task:
    return Task(
        id=strawberry.ID(str(dto.id)), title=dto.title, due_at=dto.due_at,
        status=dto.status, is_overdue=dto.is_overdue, origin=dto.origin,
        original_input=dto.original_input, created_at=dto.created_at,
        updated_at=dto.updated_at,
    )
```

### The published service `capture` depends on

```python
# app/domains/records/services/records_service.py
class RecordsService:
    def __init__(self, *, task_repository: TaskRepository) -> None:
```

### The two ports `capture` declares

```python
# app/domains/capture/interfaces/ports.py
class TaskCreationPort(Protocol):
    async def create_task(
        self, *, user_id: UUID, title: str, due_at: datetime | None,
        original_input: str,
    ) -> TaskDTO: ...


class ExtractionPort(Protocol):
    async def extract_task_fields(
        self, *, user_id: UUID, prompt: str,
    ) -> ExtractionResult: ...
```

`ExtractionResult` is gateway's own union, imported from `gateway.public`,
per the correction above. The port's return type crossing is the port's own
declaration, in capture's words — it names the type it needs, it does not
redefine it.

### The adapters

```python

# app/domains/capture/adapters/gateway_extraction_adapter.py
from app.domains.gateway.public import ExtractInteractor, ExtractionRequest
from app.domains.capture.constants import TASK_EXTRACTION_SCHEMA, TASK_EXTRACTION_INSTRUCTION


class GatewayExtractionAdapter:
    def __init__(self, *, extract_interactor: ExtractInteractor) -> None:
        self.extract_interactor = extract_interactor

    async def extract_task_fields(self, *, user_id: UUID, prompt: str) -> ExtractionResult:
        return await self.extract_interactor.extract(
            user_id=user_id,
            request=ExtractionRequest(
                prompt=prompt, schema=TASK_EXTRACTION_SCHEMA,
                instruction=TASK_EXTRACTION_INSTRUCTION,
            ),
        )
```

`TASK_EXTRACTION_SCHEMA` requires `title`, makes `due_at` optional and
nullable. A missing `title` or a null `due_at` in a successful `Extraction` is
what `SubmitCaptureInteractor` reads to decide which field to ask about — not
a keyword heuristic. The canvas prototype's `DATE_WORDS` array was a mockup
stand-in for this call and is not carried into the real implementation.

### The interactor

```python
class SubmitCaptureInteractor:
    def __init__(
        self, *, pending_capture_repository: PendingCaptureRepository,
        task_creation: TaskCreationPort, extraction: ExtractionPort,
        task_repository: TaskRepository,
    ) -> None: ...

    async def submit_capture(
        self, *, user_id: UUID, raw_input: str,
    ) -> CaptureResult:
        """Validates first, then routes by command. Raises nothing: every
        outcome, success or failure, is a return, mirroring gateway's own
        ExtractInteractor rather than raising past this boundary.
        """
        self._validate_not_empty(raw_input=raw_input)
        self._validate_length(raw_input=raw_input)
        ...  # route: non-command, unrecognised, /tasks, or /add-task
             # (the only path that calls ExtractionPort)
```

No `@map_errors` on `capture`'s resolvers: every one of the nine outcomes is a
plain return, so there is nothing for the decorator to catch. Validation
failures (empty input, over the 500-character cap) are the one place this
slice does raise — a `ValueError` before any I/O, since an empty or oversized
mutation input is a client bug, not a `CaptureResult` outcome the design
draws a screen for.

## 6. Error handling

| Failure | Detected by | User sees | System does |
|---|---|---|---|
| Empty input submitted | Interactor validation | Nothing happens, no turn added | No I/O, no row written |
| Input over 500 characters | Client validation, then server as a backstop (AD-4) | Input blocked from submitting past 500 chars | Server rejects with a `ValueError` if a client bypass reaches it; not a `CaptureResult` member |
| No command matches | `SubmitCaptureInteractor` | `UnrecognisedCommand`, closest matches by prefix | Nothing recorded |
| Required field missing from extraction | `SubmitCaptureInteractor` reads the `Extraction.data` | `PendingQuestionCreated` | One `pending_captures` row written |
| Gateway returns any of its four failure types | Passed straight through | The matching refusal card, per build plan §7 | Gateway already wrote its own `ai_usage` row; capture writes nothing |
| Answering a pending capture that does not exist or belongs to another user | `AnswerPendingCaptureInteractor`, repository returns none, RLS as the second lock | Not found, mapped to a GraphQL error (not a union member — there is no screen for this, since the frontend never holds an ID it did not receive from its own account) | Nothing written |
