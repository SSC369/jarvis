## 1. What works when this lands

A caller asks the gateway for a structured extraction and receives one of six
typed outcomes. The call is refused before reaching the model if the user is over
their daily limit, abandoned if it exceeds its time budget, and recorded in
`ai_usage` either way. The credential exists in one object and appears in no
response, log, or error.

Proven by an integration test against the real provider, not a screen. The PRD
records that as a deliberate exception.

## 5. Internal contracts

### The provider boundary

```python
class ModelProvider(Protocol):
    async def generate(self, request: ExtractionRequest) -> ProviderResult: ...
```

**LangChain lives below this Protocol, never above it.** `ExtractionService`
imports nothing from LangChain. If LangChain types reached the service we would
have swapped our abstraction for theirs, and rule T4 would hold in name only.
Moving off LangChain is then one file.

### The four steps

```python
class ExtractionService:
    def __init__(
        self,
        provider: ModelProvider,
        usage_repository: UsageRepository,
        allowance_service: AllowanceService,
        settings: Settings,
    ) -> None: ...

    async def extract(
        self, user_id: UUID, request: ExtractionRequest
    ) -> ExtractionResult: ...
```

1. Allowance. Refuse without calling out.
2. Provider, under a timeout.
3. Usage row, always.
4. Return a union member.

Step 3 runs for every path that reached step 2. That is FR-13, and it is the step
most likely to be skipped on an error branch.

## 6. Decisions this slice proposes

### 6.1 Amend AD-8: write usage in its own transaction

AD-8 puts the usage row in the caller's transaction. This proposes its own short
transaction, committed as soon as the provider returns.

| | AD-8 | Proposed |
|---|---|---|
| Connection held across an 8 second network call | Yes | No |
| Row survives the caller's later work failing | No | Yes |
| Failed provider calls recorded | Only if the caller commits | Always |

The money is spent the moment the model answers. If the caller's work then rolls
back, AD-8 discards a row for a call that really happened, contradicting FR-13
and FR-15 and understating usage against G4.

Atomicity between the caller's work and the usage row is given up, correctly:
they are not one fact. A process death between answer and commit loses one
record, unavoidable without two-phase commit.

### 6.2 What LangChain costs, and where it is paid

`with_structured_output(schema)` enforces the response shape, which is FR-16 and
most of FR-18's `malformed_result` case. That is the reason to use it.

> **This section was wrong, and is corrected here rather than quietly fixed.**
> It predicted that telling a quota error from an outage from a timeout would
> mean unwrapping to the underlying `google-genai` exceptions, making the adapter
> carry more mapping code than a direct SDK call. That is true of LangChain 0.x.
> LangChain 1.x normalises provider failures into a typed hierarchy,
> `ModelRateLimitError`, `ModelTimeoutError`, `ModelConnectionError` and others,
> and `langchain_provider.py` maps straight from those. The cost is lower than
> stated, and the adapter is simpler than a direct SDK call would have been.

FR-18's six outcomes map from LangChain's typed exceptions, in
`langchain_provider.py`, covered by T-3.6 to T-3.9.

### 6.3 Langfuse

`tech-stack.md` names Langfuse, and no requirement depends on it: `ai_usage`
satisfies FR-11 to FR-15. Its value is that it stores prompts and responses, and
Slashit's prompts carry passports, finances and family details. Rule T6 and
product principle 7 exist to make sending those to a third party deliberate.

| Option | Cost |
|---|---|
| Defer entirely | No prompt-level debugging |
| Wire with content capture **disabled** | Traces and token counts, no content |
| Wire fully | Real debugging, passports in a fourth vendor |

LangChain's callback interface makes any of the three about equally easy. Q3.

## 7. Error handling

| Failure | Caller receives | Usage row |
|---|---|---|
| Over daily limit | `UserLimitReached(limit, resets_at)` | `user_limit_reached` |
| Gateway disabled | `ProviderUnavailable` | `provider_unavailable` |
| Provider 429 or quota | `SharedQuotaExhausted` | `shared_quota_exhausted` |
| Provider 5xx or connection | `ProviderUnavailable`, after one retry | one row |
| Over 8 seconds | `ProviderTimeout` | `provider_timeout` |
| Response fails the schema | `MalformedResult(reason)` | `malformed_result` |
| Usage write fails after success | The successful result | **None.** Logged at error |

The last row is the honest one. A successful call whose insert fails still
returns the result the user paid for, and the loss is logged loudly. FR-15
forbids losing usage *silently*; NFR-3's reconciliation surfaces it.

**A retry never writes two rows.** The retry sits inside the adapter, below the
point where usage is recorded.
