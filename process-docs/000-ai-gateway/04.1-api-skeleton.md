# Implementation Sub-Plan 1 — API Skeleton

Parent: [Implementation plan index](./04-implementation-plan.md)
Context: [PRD](./01-prd.md) · [Build plan](./03-build-plan.md)

Buildable from this document plus the index. It restates nothing that lives
there.

## 1. What works when this lands

`uvicorn app.main:app` starts, `GET /health` returns `200 {"status":"ok"}`, and
`POST /graphql` answers an introspection query against an empty schema. The app
refuses to start when a required environment variable is missing, which is how
the credential rule of FR-1 is enforced from the first commit rather than
retrofitted.

## 2. Requirements covered

| FR / NFR | How this slice satisfies it |
|---|---|
| FR-1 | `core/settings.py` is the only module that reads the environment. `.env` is gitignored, `.env.example` carries names and no values |
| FR-3 | `core/logging.py` installs a structlog processor that redacts any value matching a configured secret before it reaches a handler. Proven by T-1.6 |
| NFR-1 | `.gitignore` excludes `.env`. A CI secret scan is wired in this slice so it guards every later commit |
| NFR-2 | Not measurable yet. The timing middleware that will measure it is installed here |

Nothing. This is the first slice.

### Dependencies, by name

Versions are **not pinned in this document**. Inventing a version number would
breach rule 7 of the process, which requires every number to carry a source.
They are resolved from PyPI at install time and the resolved set is recorded in
the dev log and pinned in `requirements.txt`. That is task T-1.1.

| Runtime | Why |
|---|---|
| `fastapi` | The API framework |
| `uvicorn[standard]` | ASGI server |
| `strawberry-graphql[fastapi]` | GraphQL server, mounted on FastAPI |
| `pydantic-settings` | Typed settings from the environment |
| `structlog` | Structured logging |

| Dev | Why |
|---|---|
| `pytest`, `pytest-asyncio` | Test runner, async support |
| `httpx` | Async test client against the ASGI app |
| `ruff` | Lint and format |
| `mypy` | Type check, since the ruleset requires hints on every public function |

Slice 2 adds SQLAlchemy, asyncpg, Alembic and a JWT library. Slice 3 adds the
Gemini SDK and Langfuse. Each slice appends to `requirements.txt` rather than
writing the whole set up front, so an unused dependency never sits in the image.

## 5. Internal contracts

### Settings

```python
class Settings(BaseSettings):
    environment: Literal["local", "staging", "production"] = "local"
    debug: bool = False
    log_level: str = "INFO"

    model_config = SettingsConfigDict(
        env_file=".env", env_file_encoding="utf-8", extra="forbid"
    )


@lru_cache
def get_settings() -> Settings: ...
```

`extra="forbid"` is deliberate. A typo in `.env` fails at startup rather than
silently leaving a default in place.

Slice 2 adds `database_url` and the Supabase keys. Slice 3 adds
`gemini_api_key`, `gateway_enabled` and the model name. **No secret carries a
default**, so a missing one stops the process.

### Secret redaction

```python
def redact_secrets(logger, method_name, event_dict) -> dict: ...
```

A structlog processor. It walks the event dictionary and replaces any string
containing a known secret value with `[redacted]`. Registered first in the
processor chain, before anything can render. This is the mechanism behind FR-3,
and it is installed in slice 1 so no later slice has to remember it.

## 6. Error handling

| Failure | Detected by | User sees | System does |
|---|---|---|---|
| Required environment variable missing | pydantic-settings at import | Nothing. The process never serves | Exits non-zero with the field name, never the value |
| Unknown variable in `.env` | `extra="forbid"` | Nothing | Exits non-zero naming the unexpected key |
| Unhandled exception in a request | FastAPI handler | `500` with a request id and no detail | Logs the traceback through the redacting processor |
| `/health` reached while starting | — | `200` | Returns ok. It is a liveness check, not readiness. Readiness arrives in slice 2 when there is a database to check |

## 7. Test plan

| id | Level | Case | Covers |
|---|---|---|---|
| T-1.1 | integration | `GET /health` returns 200 and `{"status":"ok"}` | section 1 |
| T-1.2 | integration | `POST /graphql` with an introspection query returns 200 and a schema | section 1 |
| T-1.3 | unit | `Settings` with a required field absent raises at construction | FR-1 |
| T-1.4 | unit | `Settings` with an unknown key in the environment raises | section 5 |
| T-1.5 | integration | A 500 response body contains a request id and no traceback | section 6 |
| T-1.6 | unit | `redact_secrets` replaces a known secret appearing in a log message, a nested dict, and an exception string | FR-3, NFR-1 |
| T-1.7 | integration | Every response carries the timing header the middleware sets | NFR-2 |

T-1.6 covers the exception string case specifically, because that is how a
credential most often reaches a log: not through a deliberate log call, but
through a provider error rendered into a traceback.
